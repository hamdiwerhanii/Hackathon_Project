## Overview

**EnergyIQ** was built for the *Come Build with AI* hackathon. It is a full-stack demo for facility managers and sustainability teams who need to see where a campus is wasting energy and what fixing it would be worth.

The platform tracks four campus buildings (Science Hall, Library, Engineering Building and Student Union) using a deterministic, synthetic 24-hour dataset. On top of that data it provides:

- **Rule-based anomaly detection** for overnight energy leaks, sudden usage spikes and badly configured HVAC setpoints.
- **Savings and ROI projections**, including a 12-month seasonal forecast and break-even month.
- **AI-generated recommendations** and **ARIA**, a conversational assistant that calls the backend's own data functions (tools) so its answers come from real numbers rather than invented figures.
- An **interactive savings simulator** for trying out efficiency upgrades (HVAC, LED lighting, solar, occupancy scheduling, peak-demand reduction).

You can run the whole app **without an API key**. Every AI-backed feature has a fallback based on rules and the data, so the app stays fully functional offline. Adding a Groq key switches on real LLM output.

## Features

### Monitoring
- **Portfolio overview** with KPI cards, a 24-hour consumption chart and a status card for each building.
- **Building drill-down** with tabs to switch buildings, an hourly demand chart and HVAC zone details (temperature, humidity, fan %, status).

### Anomaly Detection (`backend/services/alertEngine.js`)
- **Energy leaks (critical):** two or more consecutive off-hour readings (23:00–05:00 UTC) above 1.5× the building's expected idle load.
- **Usage spikes (warning):** an hour that jumps more than 1.6× above the previous hour *and* is more than 1.3× the daily average.
- **HVAC setpoint (info):** setpoint at or below 18 °C, outside the recommended 19–21 °C range.
- Alerts are sorted by severity. You can filter them by severity and status and mark them *acknowledged* or *resolved* in the UI.

### Savings & Forecasting
- Baseline vs. optimized cost for each building (leak hours clamped to idle load, plus 8% general tuning).
- 12-month projection with a seasonal factor, cumulative savings, ROI and break-even month against an assumed $15,000 retrofit cost.

### AI
- **AI Insights:** six portfolio-wide recommendations (category, priority, effort, monthly/annual $ savings) generated by Groq. They can be filtered by priority and effort. Results are cached in memory, but only successful AI responses are cached, so a failed call is retried on the next request.
- **ARIA assistant:** a floating chat widget on every page. It is backed by a tool-calling agent loop (up to 4 tool iterations) with six tools:
  `get_alerts`, `get_savings_summary`, `get_recommendations`, `get_invoices`, `get_building_zones`, `simulate_savings`.

### Operations
- **Invoices:** a deterministic 3-month electricity invoice history for each building (Paid / Pending / Overdue), with filters, search and a drag-and-drop upload area.
- **Savings simulator:** five sliders that update the results live. They show monthly/annual savings, kWh reduction, CO₂ reduction, investment and payback period. The frontend and the AI agent use the same formulas, so their numbers always match.
- **Add Building wizard:** a 3-step form that registers a new building through `POST /api/buildings`.
- **Light / dark theme** toggle, saved in `localStorage`.

## Architecture

```
┌────────────────────────────┐        HTTP / JSON         ┌──────────────────────────────┐
│  Next.js frontend (:3000)  │ ─────────────────────────▶ │  Express API (:4000)         │
│  pages · React Query hooks │                            │  routes/ → services/         │
│  ARIA chat widget          │ ◀───────────────────────── │  alert / savings / invoice / │
└────────────────────────────┘                            │  simulator engines           │
                                                          │        │                     │
                                                          │        ▼                     │
                                                          │  data/energy.json            │
                                                          │        │ (optional)          │
                                                          │        ▼                     │
                                                          │  Groq API (LLM + tool calls) │
                                                          └──────────────────────────────┘
```

The frontend calls the API through a small typed client (`frontend/lib/api/*`). The base URL comes from `NEXT_PUBLIC_API_URL` and falls back to `http://localhost:4000`.

## Getting Started

### Prerequisites

- **Node.js 18 or newer.** The backend uses the built-in `fetch`, and Next.js 15 requires 18.18+.
- npm
- *(Optional)* A free Groq API key from <https://console.groq.com>

### 1. Clone the repository

```bash
git clone https://github.com/hamdiwerhanii/Hackathon_Project.git
cd Hackathon_Project
```

### 2. Start the backend (port 4000)

```bash
cd backend
npm install
cp .env.example .env      # optional; add GROQ_API_KEY to enable real AI
npm start                 # or: npm run dev  (auto-restart with node --watch)
```

Check that it is running: `curl http://localhost:4000/api/health` should return `{"status":"ok"}`.

### 3. Start the frontend (port 3000)

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Open <http://localhost:3000>.

### Available scripts

| Location | Script | Description |
|---|---|---|
| `backend` | `npm start` | Run the API with Node |
| `backend` | `npm run dev` | Run the API with `node --watch` (auto-reload) |
| `frontend` | `npm run dev` | Next.js dev server (Turbopack) |
| `frontend` | `npm run build` | Production build (Turbopack) |
| `frontend` | `npm start` | Serve the production build |
| `frontend` | `npm run lint` | Run ESLint |

## Environment Variables

### Backend (`backend/.env`)

| Variable | Description | Default / Example |
|---|---|---|
| `PORT` | Port the Express server listens on | `4000` |
| `GROQ_API_KEY` | Groq API key. If left empty, all AI features use their data-based fallbacks | *(empty)* |
| `GROQ_MODEL` | Model that writes the AI Insights recommendations | `openai/gpt-oss-20b` |
| `GROQ_AGENT_MODEL` | Model that powers ARIA's tool calling (a stronger model gives more reliable function calls) | `openai/gpt-oss-120b` |

### Frontend (`frontend/.env.local`, optional)

| Variable | Description | Default / Example |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | Base URL of the backend API | `http://localhost:4000` |

### Enabling real AI (Groq)

1. Create a free API key at <https://console.groq.com>.
2. Set `GROQ_API_KEY=your_key` in `backend/.env`.
3. Restart the backend.

## API Reference

Base URL: `http://localhost:4000`. All endpoints return JSON. No authentication is required.

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/health` | Health check, returns `{ "status": "ok" }` |
| `GET` | `/api/energy` | All buildings with hourly usage, zones and metadata |
| `GET` | `/api/energy/:id` | A single building (e.g. `bldg-01`). Returns `404` if not found |
| `GET` | `/api/alerts` | Detected leaks, spikes and setpoint issues, sorted by severity |
| `GET` | `/api/recommendations` | Six portfolio recommendations (AI or rule-based fallback) |
| `GET` | `/api/savings` | Baseline vs. optimized daily cost for each building |
| `GET` | `/api/savings/summary` | Annual projection, monthly breakdown, ROI, break-even month |
| `GET` | `/api/invoices` | Generated invoice history (3 months per building) |
| `GET` | `/api/buildings` | Buildings registered through the wizard |
| `POST` | `/api/buildings` | Register a building |
| `POST` | `/api/assistant` | Chat with ARIA |

<details>
<summary><strong>POST /api/buildings</strong> request body</summary>

```json
{
  "name": "Arts Center",
  "type": "Academic",
  "address": "12 Campus Road",
  "city": "Tunis",
  "country": "Tunisia",
  "floors": 3,
  "area": 4200,
  "utilityProvider": "Metro Power Co"
}
```

`name`, `type`, `address`, `floors`, `area` and `utilityProvider` are required. If any is missing, the API returns `400`. On success it returns `201` with the stored building, including a generated `id` and `registeredAt`.
</details>

<details>
<summary><strong>POST /api/assistant</strong> request / response</summary>

```json
// Request
{
  "message": "What if we improve HVAC efficiency by 20% in Science Hall?",
  "history": [{ "role": "user", "content": "..." }, { "role": "assistant", "content": "..." }]
}

// Response
{
  "reply": "…",
  "toolsUsed": ["simulate_savings"],
  "usedFallback": false
}
```

`message` is required. Only the last 10 valid `user`/`assistant` history entries are forwarded to the model.
</details>

## How the Numbers Are Calculated

- **Savings:** for each building, off-hour leak readings are reduced to the expected idle load and every other hour gets an 8% optimization. Cost = kWh × the building's `costPerKwh`.
- **Monthly projection:** daily cost × days in the month × a seasonal factor `1 + 0.15·cos(2π(m−6)/12)`. ROI and break-even month assume a $15,000 implementation cost.
- **Simulator:** the levers are weighted shares of monthly cost (HVAC 38%, lighting 20%, occupancy 14%, peak demand 15%), plus $112/month per kW of solar. Total savings are capped at 78% of cost. CO₂ uses 0.00049 t/kWh. Investment and payback come from a fixed cost per lever unit.

## Deployment

The repository includes configuration for a split deployment:

- **Frontend → Netlify** (`netlify.toml`): base directory `frontend`, build command `npm run build`, and the `@netlify/plugin-nextjs` plugin.
- **Backend → Render** (`render.yaml`): a Node web service named `energyiq-backend` with root directory `backend`, start command `npm start`, and `GROQ_API_KEY` (set as a secret), `GROQ_MODEL` and `GROQ_AGENT_MODEL` as environment variables.

When you deploy, set `NEXT_PUBLIC_API_URL` on Netlify to the Render service URL. Otherwise the frontend keeps calling `http://localhost:4000`.

## AI Usage Disclosure

- **Model provider:** Groq (`openai/gpt-oss-20b` and `openai/gpt-oss-120b`), through its OpenAI-compatible API.
- **Where AI is used:** (1) writing the AI Insights recommendation cards from live usage and alert data; (2) ARIA, a tool-calling assistant that queries the app's own backend (alerts, savings, invoices, zones, simulator) so its answers are based on real numbers.
- **Data:** entirely synthetic, deterministic mock data generated for this demo. No real personal or proprietary data is used.
- **Fallback plan:** every AI-backed feature has a deterministic fallback. It runs automatically when no API key is set or a request fails.
- **Human oversight:** recommendations and simulator results are shown for a person to review. The AI never acts on building systems by itself.

## Project Status and Roadmap

This is a hackathon prototype. Some parts are intentionally simplified:

- **Data is static.** All readings come from `backend/data/energy.json`. There is no live meter or BMS integration.
- **No database.** Buildings added through the wizard are kept in server memory, are lost on restart, and are not added to the monitored dataset.
- **UI-only state.** Alert acknowledge/resolve actions and invoice uploads are stored only in the browser session. They are not saved on the backend, and uploaded files are not parsed.
- **No authentication** or multi-tenant support.
- **No automated tests** are included yet.

Possible next steps: persistent storage (e.g. PostgreSQL), real meter/IoT data ingestion, server-side alert workflows, invoice parsing, user accounts, and a test suite.
